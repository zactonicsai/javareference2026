# aks-sso-platform

Three independent building blocks for a team platform on Azure Kubernetes Service with single sign-on:

| Directory | Tool | Creates | Hand-off to the next step |
|-----------|------|---------|---------------------------|
| [`01-infra/`](01-infra/README.md) | Terraform (azurerm) | Resource group, VNet + NSG, **one public IP with a DNS name**, AKS (CNI overlay + Cilium, autoscaled zonal pools), Container Insights + Managed Prometheus + alerts, ACR, optional Grafana | public IP name/RG, cluster name, ACR (`.platform/infra.env`) |
| [`02-istio-gateway/`](02-istio-gateway/README.md) | Terraform → Helm | Istio 1.31 (official charts), ingress gateway bound to that IP, **self-signed certificate**, `Gateway istio-ingress/public-gateway` for all future VirtualServices, mesh policy, PodMonitors | public URL, gateway name, cert (`.platform/gateway.env`) |
| [`03-apps-keycloak/`](03-apps-keycloak/README.md) | Helm + scripts | **Keycloak 26** (realm `appsteam`: admin / project2 / project3 + default users), the **Java 25 Spring Boot launchpad** (Tailwind, login-restricted page, group-restricted project pages, live status, unavailable-service notice), `sso-proxy` chart + `add-service.sh` to put any service behind SSO | — |

Each directory works on its own (02 on any AKS cluster, 03 on any cluster with an Istio `Gateway`); the
`.platform/*.env` files only save you typing. Every directory has `scripts/test.sh` (checks, exit code = failures)
and a `cluster-info.sh` that lists what is running.

```
                    01-infra                      02-istio-gateway                 03-apps-keycloak
            ┌──────────────────────┐        ┌──────────────────────────┐    ┌─────────────────────────────┐
Internet ──▶│ NSG 80/443 → PIP     │──────▶ │ Azure LB → istio-ingress │──▶ │ /auth      Keycloak + Postgres│
            │ (DNS label, static)  │        │ TLS: self-signed (SANs)  │    │ /          Launchpad (Spring) │
            │ AKS + monitoring+ACR │        │ Gateway public-gateway   │    │ /project2/ sso-proxy → nginx  │
            └──────────────────────┘        └──────────────────────────┘    │ /<next>/   add-service.sh     │
                                                                            └─────────────────────────────┘
```

## Quick start (macOS/Linux; ~30 minutes end to end)

```bash
az login
# 1. infrastructure (10-15 min)
(cd 01-infra && cp terraform.tfvars.example terraform.tfvars && scripts/apply.sh && scripts/test.sh)
# 2. gateway + certificate (5 min)
(cd 02-istio-gateway && scripts/apply.sh && scripts/test.sh && scripts/trust-cert.sh)
# 3. SSO + apps (image build 5 min, install 5 min)
(cd 03-apps-keycloak && scripts/build-image.sh && scripts/install.sh && scripts/test.sh --login alice:alice123)
# optional: a second service behind SSO
(cd 03-apps-keycloak && examples/project2-site/install.sh)
```

Then open `https://<fqdn>/` (the URL is printed by each step; `terraform output public_url` in 02) and sign in as
`alice / alice123` (project2) or `admin / admin123`.

Tools: Azure CLI, Terraform ≥ 1.9, kubectl, Helm ≥ 3.10, curl, openssl, python3. No local Docker or JDK: the Spring
Boot image is built by `az acr build`. Subscription roles: Contributor + User Access Administrator.

## Design in one page

* **Network first, apps last.** The public IP and NSG are the only things the outside world sees; they are created
  once in 01 and survive cluster or gateway rebuilds. The NSG allows 80/443 from `allowed_source_cidrs` to that IP and
  denies everything else from the Internet (`01-infra/scripts/allow-ip.sh --me` locks it to your laptop).
* **One gateway, path-based routing, one certificate.** Every service is a `VirtualService` on
  `istio-ingress/public-gateway` with its own prefix (`/auth`, `/project2/`, …) — no DNS or cert work per service.
  The self-signed cert is generated by Terraform with the IP's DNS name as SAN; swap it for cert-manager later without
  touching anything else (the Gateway only knows the secret name `gateway-tls`).
* **Keycloak owns identity; apps register themselves.** Groups (`admin`, `project2`, `project3`) carry the
  authorisation. Each app's Helm chart creates its own OIDC client with a hook Job and deletes it on uninstall, so
  services can be added and removed independently. Browser traffic to Keycloak goes through the gateway; pod traffic
  uses the in-cluster Service — no OIDC discovery over the self-signed URL.
* **Two ways to protect a service.** Apps that speak OIDC (the launchpad) do it themselves; everything else goes
  behind the generic `sso-proxy` chart (oauth2-proxy with group checks) — `scripts/add-service.sh` does proxy, client,
  route and launchpad tile in one go.
* **Monitoring is on from the start.** Container Insights (JSON logs from Istio, Keycloak and the app), Managed
  Prometheus with PodMonitors (Istio, Keycloak, launchpad, oauth2-proxy), four platform alerts, optional Grafana. The
  launchpad adds a user-facing layer: it health-checks every tile and shows a notice page instead of an error.
* **Secure defaults.** Non-root, read-only root FS, dropped capabilities, seccomp; NetworkPolicies (Cilium) between
  gateway, apps and Postgres; CSRF, CSP, Secure/HttpOnly cookies, PKCE; secrets generated once into git-ignored files;
  Keycloak in production mode with Postgres, brute-force protection and admin events on.
* **Honest limitations.** Single replicas (HA knobs exist: `high_availability` in 02, `replicas`/`autoscaling` in
  03), in-cluster Postgres on a managed disk (point `postgres.externalUrl` at Azure Database for PostgreSQL for
  production), self-signed TLS, demo passwords in `values.yaml`. Egress is open; the Istio add-on is not used (see 01).

## Layout

```
aks-sso-platform/
├── 01-infra/           versions/providers/variables/main/aks/monitoring/outputs.tf, terraform.tfvars.example,
│                       backend.tf.example, scripts/{apply,destroy,test,cluster-info,allow-ip,lib}.sh, README.md
├── 02-istio-gateway/   versions/providers/variables/main/istio/outputs.tf, charts/gateway-config/,
│                       scripts/{apply,destroy,test,trust-cert,lib}.sh, README.md
├── 03-apps-keycloak/   charts/{keycloak,launchpad,sso-proxy}/, launchpad/ (Gradle + Spring Boot + Dockerfile),
│                       services.d/, examples/project2-site/, scripts/{install,build-image,add-service,test,
│                       cluster-info,uninstall,lib}.sh, README.md
├── .platform/          generated hand-off files and secrets (git-ignored)
└── .gitignore
```

## Tear-down

```bash
(cd 03-apps-keycloak && scripts/uninstall.sh --purge)   # optional: everything dies with the cluster anyway
(cd 02-istio-gateway && scripts/destroy.sh)
(cd 01-infra && scripts/destroy.sh)                      # deletes the resource group
```
